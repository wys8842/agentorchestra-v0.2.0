# Tools 模块

> Agent 能力的统一封装层：一套 `Tool` 协议、一个注册表、一条带熔断/追踪/指标/临时禁用的执行管道；所有内置与自定义能力都以工具形式注入 Agent。规范路径 `agentorchestra.capability.tools.*`，经典路径 `agentorchestra.tools.*` 依然可用。

## 设计动机与原则

1. **能力与推理解耦**：LLM 只负责"决定做什么"，怎么做由工具决定。工具只依赖一个标准协议（`Tool.run(parameters) -> ToolResponse`），Agent 与具体实现零耦合。
2. **单一执行入口**：`ToolRegistry.execute_tool / async_execute_tool` 是唯一的工具执行通道，熔断检查、临时禁用、耗时统计、追踪 span、指标埋点、错误归一都在这一条管道内完成，业务代码不会绕过（见 `registry.py`）。
3. **响应可结构化**：一切结果都走 `ToolResponse(status/text/data/error_info/stats/context)`，LLM 拿文本、程序拿 data、监控拿 stats，错误用统一错误码，避免"字符串满天飞"。
4. **默认防御**：熔断器默认开启（连续失败自动禁用）、输入参数在解析层被归一为 dict、文件工具硬拦截路径穿越、`old_string` 必须唯一匹配、乐观锁检测写冲突，减少误操作与损坏面。
5. **临时隔离用 contextvars + RAII**：子代理运行时用 `temporary_tool_filter` 以 `with` 块临时禁用工具，`finally` 强保证退出后自动恢复，且按 asyncio 任务隔离，不污染其他任务。
6. **两种注册形态**：既支持面向对象（`Tool` 子类），也支持轻量函数直注册（`register_function`），覆盖"随手一个函数也能当工具"的场景。
7. **内置工具是可复用的"规范实现"**：读改写文件带乐观锁、TodoWrite 带声明式单线程纪律、DevLog 结构化沉淀决策、MCP 适配远程协议，它们同时是自定义工具的写法范本。

## 这样设计的好处

- 给 Agent 加能力 = 注册一个工具，不需要改 Agent 代码；Agent 与工具能力互相可插拔。
- 熔断、追踪、指标集中在一个入口，任何工具（含第三方函数）自动获得一致的可观测性，而不是每个工具自己埋点。
- 统一响应协议让 Agent 可以简单判断"成功 / 部分成功 / 失败"，重试与摘要逻辑无需感知具体工具。
- 文件工具的乐观锁 + 原子写 + 自动备份，让"读-改-写"多轮循环可安全并发，减少覆盖式损坏。
- 工具过滤（read-only / full / 自定义）与子代理机制配合，天然支撑"explore 只读、code 可写"的分权。

## 功能清单

### 1. Tool 协议（base.py）

- `Tool(name, description, expandable=False, read_only=False)`：抽象基类，子类必须实现两个方法：
  - `run(self, parameters: Dict[str, Any]) -> ToolResponse`：核心执行；
  - `get_parameters(self) -> List[ToolParameter]`：声明参数（`name/type/description/required/default`，`type` 为 `string/integer/number/boolean/array/object`）。
- `read_only` 标志是 `ReadOnlyFilter` 判断"是否只读工具"的依据（见 tool_filter）。
- 便捷方法：
  - `run_with_timing()`：包装 `run()`，捕获未处理异常并返回 `INTERNAL_ERROR` 响应，同时给响应填充 `stats["time_ms"]` 与 `context["params_input"]/["tool_name"]`；
  - `arun()`：默认在线程池里执行同步 `run_with_timing()`，子类可重写为真异步；`arun_with_timing()` 再包一层异常归一。
  - `validate_parameters()`、`to_dict()`、`to_openai_schema()`：后者把 `ToolParameter` 转换成 OpenAI function calling schema（数组类型默认 `items={"type":"string"}`，默认值并入描述）。
- **可展开模式（expandable）**：`expandable=True` 时注册表会调用 `get_expanded_tools()` 把父工具拆成多个独立子工具注册。默认实现扫描父工具上被 `@tool_action(name, description)` 标记的方法，自动生成 `AutoGeneratedTool`（方法名 `_add_memory` → 子工具名 `<父名>_add_memory`，参数从方法签名 + docstring 解析）。
- `ToolParameter` 继承 pydantic `BaseModel`，`to_dict()` 即 `model_dump()`。

### 2. 统一响应协议（response.py）

`ToolResponse` 是 dataclass，字段：`status: ToolStatus`（`SUCCESS`/`PARTIAL`/`ERROR`）、`text`（给 LLM 读）、`data`、`error_info`（仅 error 时：`{"code","message"}`）、`stats`、`context`。

- 构造器推荐三个类方法：`ToolResponse.success(text, data=...)`、`ToolResponse.partial(...)`、`ToolResponse.error(code, message, ...)`。
- 序列化：`to_dict()`（error 字段落到 `"error"` 键）/`to_json()`；反序列化 `from_dict()`/`from_json()`。

### 3. 错误码（errors.py）

`ToolErrorCode` 是全字符串常量类，无枚举依赖，方便 JSON 传输。分组：

| 分组 | 错误码 |
|---|---|
| 资源 | `NOT_FOUND` `ACCESS_DENIED` `PERMISSION_DENIED` `IS_DIRECTORY` `BINARY_FILE` |
| 参数 | `INVALID_PARAM` `INVALID_FORMAT` |
| 执行 | `EXECUTION_ERROR` `TIMEOUT` `INTERNAL_ERROR` |
| 状态 | `CONFLICT`（乐观锁冲突） `CIRCUIT_OPEN`（熔断拒绝） |
| 网络 | `NETWORK_ERROR` `API_ERROR` `RATE_LIMIT` |

提供 `get_all_codes()` / `is_valid_code()`。熔断器用这套码识别"预期内错误"（见下）。

### 4. ToolRegistry（registry.py）

- 注册：`register_tool(tool, auto_expand=True)`（同名会告警并覆盖）；`register_function(func, name=None, description=None)`，兼容旧的 `register_function(name, description, func)` 调用顺序。函数名与 docstring 首行可作为缺省 name/description。
  - **重要约定**：函数工具执行时被调用为 `func(parameters)`，即参数是"解析后的参数字典"这一个位置参数；因此函数应写成 `def add(params)` 并从 `params["a"]` 取值，而不是声明两个形参。
- 查询/管理：`get_tool(name)`、`get_function(name)`、`unregister(name)`、`list_tools()`、`get_all_tools()`、`get_tools_description()`（拼提示词用）、`clear()`。
- 执行（统一管道）：
  - `execute_tool(name, input_text)` / 异步 `async_execute_tool(name, input_text)`，`input_text` 可为 `dict`、JSON 字符串或普通字符串（非 JSON 字符串被包成 `{"input": ...}`）。
  - 管道顺序：**① 临时禁用检查**（命中即返回 `NOT_FOUND`，不进熔断/执行）→ **② 熔断检查**（open 时返回 `CIRCUIT_OPEN` 且带恢复倒计时）→ **③ 参数解析** → **④ 执行**（Tool 走 `run_with_timing`，函数走 `func(parameters)` + timing 包装）→ **⑤ 结果记录**（熔断器记结果 + 指标埋点 `record_tool_call`）→ **⑥ 追踪 span 结束**（error 状态打标）。
  - 工具不存在返回 `NOT_FOUND`；Tool/函数抛出异常都被归一成 `EXECUTION_ERROR`。
- 只读元数据缓存：`set_read_metadata / get_read_metadata / clear_read_cache`，供文件乐观锁跨调用传递 `file_mtime_ms`。
- 模块级单例 `global_registry = ToolRegistry()`，Agent 常用它，也便于进程内共享。

### 5. 临时工具禁用（registry.py `temporary_tool_filter`）

`with temporary_tool_filter({"Write", "Bash"}):` 块内，被禁工具在 `execute_tool` 中被直接拒绝（`NOT_FOUND`），`list_tools()` 也不再列出；退出 with 自动恢复。基于 `contextvars`，每个 asyncio 任务独立持有禁用集合。

### 6. CircuitBreaker（circuit_breaker.py）

状态机 `Closed → Open（连续失败达阈值）→ Closed（超时后自动恢复）`。

- 参数：`failure_threshold=3`、`recovery_timeout=300`（秒）、`enabled=True`。
- `record_result(tool_name, response)`：仅当响应为 `ERROR` 且错误码**不在** `NON_FAILURE_CODES` 时才累计失败。`NON_FAILURE_CODES` 视作"预期内业务错误"，包含 `NOT_FOUND / INVALID_PARAM / INVALID_FORMAT / ACCESS_DENIED / PERMISSION_DENIED / IS_DIRECTORY / BINARY_FILE / CONFLICT / TIMEOUT`——因此"工具不存在""参数错""被禁用"这类正常拒绝不会把熔断器打爆。
- 手动干预：`open()/close()`；状态查询 `get_status(name)`（`state/failure_count/open_since/recover_in_seconds`）与 `get_all_status()`。

### 7. 工具过滤（tool_filter.py）

服务子代理与只读 Agent 场景：

- `BaseToolFilter`：`filter(all_tools)` / `is_allowed(name)`，附 `filter_with_registry(registry)` 可感知 Tool 元数据。
- `ReadOnlyFilter`：只允许只读工具。推荐入口 `filter_with_registry()`（按 `Tool.read_only` 属性），对函数工具回退到名称白名单 `READONLY_TOOLS`（含 `Read`、`Skill`、`python_calculator` 等）。
- `FullAccessFilter`：默认全放行，仅排除危险黑名单（`Bash`/`Terminal`/`Execute` 等）。
- `CustomFilter(allowed, denied, mode="whitelist"|"blacklist")`：显式白/黑名单。

### 8. 内置工具（builtin/）

- **CalculatorTool**（`python_calculator`，只读）：AST 白名单求值，`OPERATORS` 覆盖 `+ - * / ** ^ 一元负号`，`FUNCTIONS` 含 `abs/round/max/min/sum/sqrt/sin/cos/tan/log/exp/pi/e`。只接受表达式文本（`input` 或 `expression` 键），不执行任意代码。语法错误→`INVALID_FORMAT`，其余→`EXECUTION_ERROR`。
- **ReadTool / WriteTool / EditTool / MultiEditTool**（file_tools.py）：公共能力是 `FileToolMixin._resolve_path`（解析后必须位于 `working_dir` 内，`..` 逃逸与越界绝对路径直接抛 `PermissionError` → 响应错误码 `PERMISSION_DENIED`）与 `_backup_file`（写前备份到 `<目录>/.backups/`）。
  - `ReadTool`：读文件（`offset`/`limit`，默认 0/2000）或列目录；读文件时把 `file_mtime_ms`/`file_size_bytes` 写入传入的 `ToolRegistry`（构造参数 `registry=`），供后续写操作做乐观锁。
  - `WriteTool`：传了 `file_mtime_ms` 且与磁盘不一致 → `CONFLICT`；用 `runtime.core.utils.atomic_write`（临时文件+替换）落盘。
  - `EditTool`：`old_string` 必须唯一匹配，否则 `INVALID_PARAM`；成功后返回 `backup_path`。
  - `MultiEditTool`：先全部校验（唯一匹配）再一次性替换，保证原子性。
- **TodoWriteTool**：声明式提交完整列表 `{"content","status"}`；强制"最多 1 个 `in_progress`"（违反→`INVALID_PARAM`）；自动生成 Recap 文本；`action=create|update|clear`；持久化到 `<project_root>/memory/todos/todoList-<ts>.json`。附数据类 `TodoItem`/`TodoList`（`get_stats/get_in_progress/...`）。
- **DevLogTool**：七类结构化日志 `CATEGORIES`（decision/progress/issue/solution/refactor/test/performance），操作 `append/read/summary/clear`，支持按 `category/tags/limit` 过滤；落盘 `<project_root>/memory/devlogs/devlog-<session_id>.json`。
- **TaskTool**：`run_as_subagent` 的桥，参数 `task/agent_type(react|reflection|plan|simple)/tool_filter(readonly|full|none)/max_steps`，子代理返回摘要并包成 `success` 或 `partial` 响应（未完全完成时 `PARTIAL`）。
- **SkillTool**：按 `skill` 名从 `SkillLoader` 加载技能，支持 `$ARGUMENTS` 占位替换与资源提示；技能缺失→`NOT_FOUND`。注入方式是 tool_result（不改 system_prompt），缓存友好。
- **MCPToolAdapter / MCPServerManager**：从 `mcp.json`（`{"mcpServers": {...}}`）读取 server，支持 stdio（本地命令）与 streamable http（`url`），后台事件循环常驻连接，每个 MCP 工具适配为 `Tool`（名字加 `<server>_` 前缀防冲突）。`mcp` SDK 未安装时 `connect_all()` 抛 `ImportError`，由上层降级（框架其他功能不受影响）。`close_all()` 关闭连接并停止后台线程。

## 使用说明

### import 路径

```python
# 规范路径（领域化）
from agentorchestra.capability.tools import ToolRegistry, ToolResponse, ToolStatus, ToolErrorCode
from agentorchestra.capability.tools.base import Tool, ToolParameter
from agentorchestra.capability.tools.circuit_breaker import CircuitBreaker
from agentorchestra.capability.tools.tool_filter import ReadOnlyFilter

# 经典扁平路径（经 _legacy 映射，同一模块对象）
from agentorchestra.tools.registry import ToolRegistry as TR2      # 与上面是同一个类

# 根包快捷导出
from agentorchestra import ToolRegistry, global_registry, CalculatorTool, calculate
```

### 场景 1：注册函数工具并执行

```python
from agentorchestra.capability.tools.registry import ToolRegistry

def add(params):                      # 统一入口约定：函数接收“参数字典”
    return params["a"] + params["b"]

registry = ToolRegistry()
registry.register_function(add, name="add_two", description="两数相加")

resp = registry.execute_tool("add_two", '{"a": 1, "b": 2}')   # 也支持直接传 dict
print(resp.status.value)     # success
print(resp.data)             # {'output': 3}
print(resp.stats)            # {'time_ms': ...}
```

### 场景 2：自定义 Tool 子类

```python
from agentorchestra.capability.tools import Tool, ToolParameter, ToolResponse

class EchoTool(Tool):
    def __init__(self):
        super().__init__(name="echo", description="原样返回输入", read_only=True)

    def get_parameters(self):
        return [ToolParameter(name="input", type="string",
                              description="要回显的文本", required=True)]

    def run(self, parameters):
        return ToolResponse.success(text=parameters["input"],
                                    data={"echoed": parameters["input"]})

registry.register_tool(EchoTool())
print(registry.execute_tool("echo", {"input": "hello"}).text)
```

### 场景 3：熔断与恢复语义

```python
from agentorchestra.capability.tools.circuit_breaker import CircuitBreaker
from agentorchestra.capability.tools import ToolResponse

cb = CircuitBreaker(failure_threshold=2, recovery_timeout=60)
for _ in range(2):
    cb.record_result("my_tool", ToolResponse.error(code="EXECUTION_ERROR", message="boom"))
print(cb.is_open("my_tool"))        # True（连续失败达阈值）
print(cb.get_status("my_tool"))     # state=open + recover_in_seconds
cb.close("my_tool")                 # 手动恢复
```

### 场景 4：子代理临时禁用与只读过滤

```python
from agentorchestra.capability.tools import ToolRegistry, temporary_tool_filter
from agentorchestra.capability.tools.builtin import CalculatorTool, TodoWriteTool

registry = ToolRegistry()
registry.register_tool(CalculatorTool())      # python_calculator（只读）
registry.register_tool(TodoWriteTool(project_root="."))   # TodoWrite（可写）

with temporary_tool_filter({"TodoWrite"}):
    print(registry.list_tools())              # ['python_calculator']：临时禁用即刻生效
    resp = registry.execute_tool("TodoWrite", {"action": "create"})
    assert resp.error_info["code"] == "NOT_FOUND"
print(registry.list_tools())                  # 块外自动恢复

from agentorchestra.capability.tools.tool_filter import ReadOnlyFilter
print(ReadOnlyFilter().filter_with_registry(registry))   # ['python_calculator']
```

### 关键常量 / 默认值

| 项目 | 默认值 | 说明 |
|---|---|---|
| `CircuitBreaker.failure_threshold` | `3` | 连续“非预期”失败多少次后熔断 |
| `CircuitBreaker.recovery_timeout` | `300` s | 熔断后自动恢复时间 |
| `CircuitBreaker.enabled` | `True` | 注册表默认自带熔断 |
| `ToolStatus` | `SUCCESS / PARTIAL / ERROR` | 完整 / 部分 / 失败 |
| `ToolRegistry.global_registry` | 进程单例 | 也可 `ToolRegistry(circuit_breaker=...)` 注入 |
| `execute_tool` 未知工具/被禁用 | → `NOT_FOUND` | 熔断前先判禁用 |

## 与其他模块的关系

- **runtime.core.utils**：`measure_elapsed_ms`、`atomic_write`、`safe_json_load`、`truncate_text` 被 registry 与多个内置工具使用（`registry.py`、`file_tools.py`、`todowrite_tool.py`、`devlog_tool.py`、`mcp_tool.py`）。
- **runtime.core.telemetry**：`execute_tool` 内部（惰性 import）调用 `tracing.get_tracer().start_span("tool.<name>")` 与 `metrics.get_metrics().record_tool_call(name, error=...)`，把工具执行接进框架追踪与指标（见 observability 模块文档）。
- **capability.skills.loader**：`SkillTool` 依赖 `SkillLoader` 按需取技能。
- **runtime.core.agent / config**：`TaskTool` 依赖 Agent 工厂与 `Config` 创建隔离子代理。
- **capability.memory**：`memory/tools.py` 中的 `MemorySaveTool`/`MemoryRecallTool` 复用本模块的 `Tool`/`ToolParameter`/`ToolResponse`/`ToolErrorCode` 协议实现（见 memory 模块文档）。
- **ontology.tool_generator**：`ObjectQueryTool`/`ObjectActionTool`/`FunctionCallTool` 由 ontology 生成并 `register_tool` 进本模块的 `ToolRegistry`（见 ontology 模块文档）。
- **runtime.capabilities.builtins**：`TraceCapability/SkillsCapability/OntologyCapability/MemoryCapability/...` 都在 Agent 装配时向 `tool_registry` 注册相应内置工具。
